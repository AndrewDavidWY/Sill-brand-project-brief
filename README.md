# 品牌项目资料梳理与口径统一

把分散的 PPT、PDF、表格和图片整理成能追溯来源的项目简报，为后续宣传文案、设计、汇报和协作提供一致的事实基础。

技能名称：`brand-project-brief` · [查看技能指令](SKILL.md)

## 适合什么时候用

- 接手一个新项目，资料很多，但定位和业务关系不清楚。
- 多份方案中的数字、名称和时间口径不一致。
- 准备做宣传或汇报，需要先区分现状、目标与待确认事项。

## 开始前准备什么

- 本轮使用的全部材料，以及用户明确指定的版本。
- 简报的用途、目标读者和需要回答的问题。
- 已经确认的名称、数据口径及仍有争议的事项。

## 工作方式

1. 盘点资料版本，区分原始材料、用户说明和历史草稿。
2. 提取定位、受众、业务结构、产业关系及关键指标。
3. 建立包含来源、单位、时间和状态的事实表。
4. 处理版本冲突，再形成简报、术语表和未决项。

## 可以得到什么

- 可供后续写作与设计使用的项目简报。
- 附文件页码或工作表位置的事实表与术语表。
- 版本冲突、缺失资料和待确认清单。

## 安装与调用

将完整仓库克隆到自己的技能目录，安装文件夹使用技能名称 `brand-project-brief`：

```sh
git clone https://github.com/AndrewDavidWY/Sill-brand-project-brief.git ~/.codex/skills/brand-project-brief
```

如果使用自定义 `CODEX_HOME`，请放到其 `skills/` 下。同名目录已经存在时先比较版本并保留自己的修改，不要直接覆盖。下载 ZIP 时，同样需保留完整文件结构，并把解压后的安装目录命名为技能名称。

在新会话中确认技能可用，再用下面的方式提出任务：

```text
使用 $brand-project-brief，梳理这几份项目材料，先解释业务板块之间的关系，再整理事实表。不要把战略目标写成已完成成果，数字冲突请并列列出。
```

## 文件与维护

- [SKILL.md](SKILL.md)：技能入口、适用范围和执行方法。

- [agents/openai.yaml](agents/openai.yaml)：界面名称、简介与调用提示。

## 使用边界

不凭空补写公司事实，不把历史助手草稿当成原始证据。材料中有记载，不等于已经独立核实；也不能仅因文件日期较新就覆盖所有旧数据。
